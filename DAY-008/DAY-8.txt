**Introduction to Functions**  
- Functions are **packaged instructions performing specific tasks**.  
- Functions in Python are created using the **`def` keyword** (short for definition).  
- The function syntax includes parentheses, which hold **parameters (arguments to the function)**; these can be empty if no parameters are used.  
- Functions cannot be completely blank; the **`pass` keyword** serves as a placeholder allowing you to define an empty function body without causing errors.  

[00:00:58]  
**Executing vs. Referencing Functions**  
- Calling a function requires appending parentheses, e.g., `helloFunc()`.  
- Without parentheses, the function itself is referenced (e.g., printing the function name shows its memory location), not executed.  
- Example:  
  - `print(helloFunc)` prints the function object reference.  
  - `helloFunc()` executes the function.  

[00:01:27]  
**Adding Function Behavior & Print Statements**  
- When a function is executed, its internal code runs, e.g., a print statement.  
- Printing the result of a function that has no `return` outputs `None`.  
- To see output from execution, use `print()` inside the function or print the value returned by the function if it has one.  

[00:02:28]  
**Code Reusability & Avoiding Duplication (DRY Principle)**  
- Functions enable **reuse of code** without duplication, which is beneficial for maintenance.  
- Example: instead of repeating a print statement multiple times, call the function multiple times.  
- This reduces work when making changes; e.g., changing punctuation in the function updates all calls automatically.  
- This strategy adheres to the **DRY (Don't Repeat Yourself)** principle, a common best practice in programming.  

[00:04:00]  
**Return Values in Functions**  
- Functions can **return values** instead of just printing.  
- Using `return` assigns the function call to a value equal to whatever the return statement specifies.  
- Example:  
  - Returning `"Hello function"` means calling `helloFunc()` produces that string.  
  - Printing `helloFunc()` then outputs that string.  
- Functions as **black boxes**: Focus on **inputs and return values**, not internal implementation initially.  

[00:05:32]  
**Chaining Methods on Return Values**  
- Returned values behave like their data types.  
- Example: Since the function returns a string, string methods like `.upper()` can be chained directly:  
  $$ \text{helloFunc()}.\text{upper}() $$  
- This demonstrates Python’s flexibility in treating function outputs as normal data types.  

[00:07:14]  
**Passing Arguments to Functions**  
- Parameters are declared within the parentheses in function definitions, enabling customization.  
- Example: defining a parameter `greeting` allows passing different greeting strings.  
- Calling the function without required arguments causes an error:  
  - Error message example: *missing 1 required positional argument 'greeting'*.  
- Arguments are passed at call time, e.g., `helloFunc("Hi")`.  

[00:08:23]  
**Local Scope of Parameters**  
- Function parameters have **local scope**: they do not affect variables outside the function.  
- This containment avoids side effects in other parts of the program.  
- For detailed coverage on scope, additional resources/videos are referenced.  

[00:08:52]  
**Default Parameter Values**  
- Parameters can have **default values**, making them optional in calls.  
- Example:  
  ```python
  def helloFunc(greeting, name="U"):
      return "{}, {}".format(greeting, name)
  ```  
- If `name` is omitted, it defaults to `"U"`; otherwise, the passed value is used.  
- Important: **required positional arguments must come before keyword arguments with defaults** to avoid errors.  

[00:10:31]  
**Arbitrary Number of Arguments: `*args` and `**kwargs`**  
- Functions can accept **arbitrary positional and keyword arguments** using:  
  - `*args` for an arbitrary number of positional arguments (received as a tuple).  
  - `**kwargs` for an arbitrary number of keyword arguments (received as a dictionary).  
- Example function:  
  ```python
  def student_info(*args, **kwargs):
      print(args)   # Tuple of positional args
      print(kwargs) # Dict of keyword args
  ```  
- Positional example: classes student is taking (`math`, `art`).  
- Keyword example: additional student information like `name="John"`, `age=22`.  

[00:12:45]  
**Unpacking Arguments with `*` and `**` at Call Site**  
- Prefixing a list with `*` unpacks the list into separate positional arguments.  
- Prefixing a dictionary with `**` unpacks it into separate keyword arguments.  
- Example:  
  ```python
  courses = ["math", "art"]
  info = {"name": "John", "age": 22}
  student_info(*courses, **info)
  ```  
- This is functionally equivalent to passing each value individually: `student_info("math", "art", name="John", age=22)`.

[00:14:55]  
**Summary of Advanced Argument Passing**  
- `*args` and `**kwargs` simplify handling variable numbers of inputs.  
- Unpacking with `*` and `**` allows flexible argument passing from lists and dictionaries.  
- This is an **advanced yet powerful feature** in Python functions for building general and reusable code.  

[00:15:22]  
**Real-World Example: Leap Year & Month Days Functions**  
- Two sample functions derived from the Python standard library were examined:  

| Function Name   | Purpose                                      | Input                    | Output                  |
|-----------------|----------------------------------------------|--------------------------|-------------------------|
| `is_leap(year)` | Determines if a given year is a leap year    | Integer year (e.g., 2020) | Boolean (True/False)    |
| `days_in_month(year, month)` | Returns number of days in given month/year | Integer year, integer month (1-12) | Integer days or error message |

- `is_leap(year)` uses the standard leap year logic:  
  - A year is leap if divisible by 4 but not 100, **or** divisible by 400.  
- A **docstring** (triple quotes after function definition) documents function behavior—a recommended good practice.  

[00:16:20]  
**Leap Year Calculation Logic Explained**  
- The conditional uses modular arithmetic to determine leap years:  
  $$ (\text{year} \bmod 4 = 0) \land (\text{year} \bmod 100 \neq 0) \quad\text{or}\quad (\text{year} \bmod 400 = 0) $$  
- This identifies leap years accurately per Gregorian calendar rules.  

[00:17:49]  
**`days_in_month(year, month)` Function Details**  
- Validates input month to be between 1 and 12 (inclusive).  
- Special case: if month is February (2) and year is leap, returns 29 days.  
- Otherwise, returns the number of days indexed from a `month_days` list where the first element is a placeholder for index alignment.  
- Returns an error string if month is invalid.

**Example Function Calls and Walkthrough**

|-----------------------------|--------------------|-------------------------------------------------|

| `is_leap(2020)`              | `True`             | 2020 is a leap year                              |
| `days_in_month(2017, 2)`     | `28`               | February in a non-leap year                       |

- When running `days_in_month(2017, 2)`:  
  - Month validity check passes (2 is valid).  
  - Call to `is_leap(2017)` returns `False`.  
  - Since it is not a leap year, returns 28 from the days list.

**Introduction to Module Importing in Python**  
- The video begins by introducing the concept of importing modules in Python.  
- Initially, it focuses on importing user-defined modules before moving toward standard library modules.  
- Example module introduced: **my_module.py**, containing:  
  - A print statement for demonstration purposes.  
  - A variable `test` set to `"test string"`.  
  - A function `find_index` that returns the index of a target value in a list or $-1$ if the value is not found.  
- The goal is to show how to reuse this function across other scripts by importing the module.

[00:00:54]  
**Importing a User-Defined Module from the Same Directory**  
- Another script, `intro.py`, contains a list variable `courses`.  
- Because `my_module.py` is in the **same directory**, Python can locate it automatically.  
- Importing the module executes all its top-level code, including print statements, confirming successful import.  
- Example usage:  
  ```python
  import my_module
  index = my_module.find_index(courses, "Math")
  print(index)
  ```  
- The function returns the correct index (1 for "Math").

[00:02:26]  
**Module Aliasing for Convenience**  
- Typing `my_module.find_index` repeatedly can be verbose.  
- Solution: use the `as` keyword to alias the module, e.g.,  
  ```python
  import my_module as mm
  index = mm.find_index(courses, "Math")
  ```  
- This shortens the invocation and improves readability—common in widely used libraries (e.g., `numpy as np`).

[00:03:30]  
**Importing Specific Components from a Module**  
- Instead of importing the whole module, one can import specific functions or variables:  
  ```python
  from my_module import find_index
  ```  
- This allows calling `find_index()` directly without the module prefix.  
- Limitation: only the imported components are accessible this way. For example, the variable `test` won’t be accessible unless explicitly imported.  
- To import multiple items:  
  ```python
  from my_module import find_index, test
  ```  
- Also possible to alias imported functions or variables, e.g.,  
  ```python
  from my_module import find_index as fi
  ```  
- Caution advised: overly short or unclear aliases can hurt code readability.

[00:05:36]  
**Importing Everything with `*` (Wildcard Import)**  
- Using:  
  ```python
  from my_module import *
  ```  
- Imports all public names from the module—functions, variables, etc.  
- This is **frowned upon** because it makes the code less maintainable and harder to debug, as it obscures the origin of functions or variables used in the script.  
- Recommended practice: explicitly import only what is needed.

[00:06:04]  
**Understanding How Python Finds Modules: `sys.path`**  
- Python searches for modules in directories listed in `sys.path`.  
- Importing the `sys` module and printing `sys.path` shows the search order.  
- Typical search order includes:  
  1. The directory of the running script (first priority).  
  2. Directories listed in the `PYTHONPATH` environment variable.  
  3. Standard library directories (built-in modules).  
  4. The `site-packages` directory (third-party packages).  
- Because `my_module.py` was initially in the script’s directory, it was found immediately.

[00:08:05]  
**Importing Modules Located Outside the Current Directory**  
- If a module is moved outside the script’s directory (e.g., to a folder on the desktop), Python will raise a `ModuleNotFoundError` unless the directory is added to `sys.path`.  

- To temporarily solve this within the script:  
  ```python
  import sys
  sys.path.append('/Users/username/Desktop/my-modules')
  import my_module
  ```  
- This method works but is not elegant or scalable because you would need to modify multiple scripts manually.

[00:09:47]  
**Setting the `PYTHONPATH` Environment Variable (Mac OS)**  
- A better practice is to add the directory permanently to the `PYTHONPATH` environment variable.  
- On Mac OS, this can be done by editing the `~/.bash_profile` (or similar shell config) file using a text editor like `nano`.  
- Add the line:  
  ```bash
  export PYTHONPATH="/Users/username/Desktop/my-modules"
  ```  
- After saving and restarting the terminal or sourcing the profile (`source ~/.bash_profile`), the module can be imported without modifying `sys.path` in the script.  
- `sys.path` will include the directory from `PYTHONPATH` when Python runs.

[00:11:52]  
**Setting the `PYTHONPATH` Environment Variable (Windows)**  
- On Windows, environment variables can be set via:  
  - Start → Right-click Computer → Properties → Advanced system settings → Environment Variables.  
  - Create a new variable named `PYTHONPATH` (uppercase).  
  - Set its value to the absolute path of the modules directory (e.g., `C:\Users\username\Desktop\my-modules`).  
- After applying and restarting Command Prompt, running Python and importing the module will work without errors.  
- `sys.path` shows the new directory after the current working directory.  

- **Note:** IDEs/editors like PyCharm, Sublime Text, or Eclipse may require separate configuration to recognize environment variables.

**Standard Library Modules and Their Importance**

- Standard library modules are bundled with Python installations and do not require additional installation.  
- They are professional, optimized implementations of common tasks and should be preferred in production over custom implementations, although writing your own can be good practice.  
- **Examples demonstrated:**

  - **math** module: mathematical functions and conversions, e.g., converting degrees to radians, trigonometric functions.  
  - **datetime** module: working with dates and times.  
  - **calendar** module: calendar utilities such as checking leap years.  
  - **os** module: interacting with the operating system, such as obtaining the current working directory.
